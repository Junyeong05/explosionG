# 연쇄 폭발 (explosionG)

모아서 쏜 폭발 한 방이 폭발형 적을 타고 번지고, 판 안에서 고른 증강이 그 연쇄를 키우는 세로 화면 모바일 로그라이트.

- 기획서: [`docs/design/game-design-v0.1.md`](docs/design/game-design-v0.1.md)
- 구조 설명: [`docs/architecture.md`](docs/architecture.md)
- 실험 기록: [`docs/design/experiments-2026-11.md`](docs/design/experiments-2026-11.md) (과충전·연쇄 잇기·벼랑 끝)

이 저장소는 **프로토 v3 개발 틀**이다. 코어 루프(게이지 모으기 → 탭 → 연쇄 → 레벨업 증강 → 보스 → 판 종료 → 영구 강화 → 다음 챕터)가 처음부터 끝까지 돌아가고, 콘텐츠를 데이터로 계속 붙여나갈 수 있게 잡아뒀다.

## 빠른 시작

```bash
npm install
```

```bash
npm run dev
```

터미널에 뜨는 `Network:` 주소를 같은 와이파이의 휴대폰 브라우저로 열면 바로 터치로 해볼 수 있다.

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 (LAN 공개). 콘솔에서 `__app.world` 로 sim 상태 확인·조작 |
| `npm test` | 규칙 테스트 (연쇄·적 종류·증강·결정론·세이브) |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 타입 검사 + `dist/` 정적 빌드 (어디든 올리면 됨) |
| `npm run autoplay -- --runs 200` | 헤드리스 자동 플레이로 밸런스 리포트 |

## 엔진: 웹(TypeScript + Canvas2D)으로 시작한 이유

기획서 오픈 질문 "Unity vs 웹 기반"에 대해, 다음 단계(프로토 v3: 테스터 5~10명, 지표 확인)에 맞춰 웹으로 잡았다.

- 링크 하나로 테스터에게 배포 → 빌드·심사 없이 하루에도 몇 번씩 수치를 바꿔 돌릴 수 있다.
- **게임 규칙(`src/sim`)은 DOM·렌더링과 완전히 분리된 순수 TS**라서 Node 에서 수백 판을 몇 초 만에 돌릴 수 있다 (자동 플레이 검증).
- 출시는 Capacitor 로 감싸 iOS·Android 앱으로 낸다. Unity 로 옮기기로 하면 `src/sim` + `src/data` 를 C# 로 옮기고 테스트를 그대로 기준으로 삼으면 된다.

## 폴더 구조

```
src/
  core/      난수(시드), 오브젝트 풀, 공간 격자, 수학 — 엔진 독립 유틸
  data/      ★ 기획 데이터: 수치(balance), 적, 보스, 챕터, 증강, 영구 강화
  sim/       ★ 게임 규칙. 결정론, DOM 없음. World(한 판), 증강 매니저, 봇
  meta/      아웃게임: 세이브, 영구 강화 구매, 판 종료 정산
  render/    Canvas2D 렌더러 + 연출(링·파티클·피해 숫자·흔들림, 전부 상한 있음)
  feedback/  사운드(WebAudio 합성), 진동, 슬로모션
  input/     포인터 → sim 명령
  ui/        메뉴 화면 (타이틀, 영구 강화, 증강 선택, 일시정지, 결과)
  app/       화면 흐름 + 고정 스텝 루프
tests/       vitest
tools/       autoplay.ts (밸런스 리포트)
docs/        기획서, 구조 문서
```

## 콘텐츠 추가하기

대부분 `src/data/` 파일에 객체 하나 추가로 끝난다.

| 추가할 것 | 파일 | 방법 |
| --- | --- | --- |
| 증강 | `data/augments.ts` | `AUGMENTS` 에 추가. 숫자 강화는 `modifyStats`, 규칙은 `hooks.onKill / onExplosion / onTick`, 획득 즉시 효과는 `onAcquire` |
| 진화 | `data/augments.ts` | `evolution: { requires, replaces }` 를 단 증강 |
| 적 | `data/enemies.ts` | `ENEMIES` 에 추가 (`spawnWeight`, `deathBlast`, `shields`, `loner` 등) 후 챕터 `roster` 에 넣기 |
| 보스 | `data/bosses.ts` | `boss.onDamaged` 로 패턴 구현 |
| 챕터 | `data/chapters.ts` | `CHAPTERS` 에 추가 (순서 = 해금 순서). 웨이브 수, 보스, 체력 배율, `roster`(어떤 적이 몇 웨이브부터) |
| 영구 강화 | `data/upgrades.ts` + `sim/stats.ts` | `MetaModifiers` 에 필드 추가 후 `apply` |
| 기본 수치 | `data/balance.ts` | ⚠ 표시는 기획서에 값이 없어 임시로 넣은 것 |

증강 훅 규칙: **훅 안에서는 적에게 직접 피해를 주지 않고 `api.spawnExplosion` 으로 큐에 넣는다.** 그래야 훅이 훅을 부르는 재귀가 없고 결과가 결정론적이다.

## 자동 플레이 (밸런스 검증)

```bash
npm run autoplay -- --runs 200 --chapter ch2
```

```bash
npm run autoplay -- --runs 200 --upgrades firepower=5,durability=2 --json autoplay-mid.json
```

기획서의 "프로토 단계에서 볼 것"을 그대로 뽑는다: 클리어율, 판 길이(목표 5~8분), 판당 최대 연쇄 분포, 사망 웨이브, 증강 선택 빈도. 봇은 사람이 아니라 **기준선**이라, 수치를 바꾼 뒤 "전보다 쉬워졌나/어려워졌나"를 비교하는 데 쓴다.

현재 임시 수치 기준 (봇 200판, 영구 강화 없음):

| 챕터 | 새 적 | 클리어율 | 탭당 처치 | 판당 최대 연쇄 (중앙) |
| --- | --- | --- | --- | --- |
| 1 | 일반·폭발형 (돌격형은 웨이브 10부터) | 82.5% | 17.1 | 63 |
| 2 | 장갑 | 63% | 14.3 | 58 |
| 3 | 보호막 | 48% | 12.4 | 52 |
| 4 | 분열 | 27.5% | 12.1 | 41 |

챕터 1은 웨이브 11~15에서 죽는다 (판 후반으로 갈수록 어려움). 챕터 2~4는 웨이브 5~8에서 많이 죽는다.
꽉 채운 탭의 중심 피해 ÷ 일반 적 체력 (챕터 1, 봇의 증강·배율 포함): 웨이브 1 = 2.0, 5 = 1.1, 10 = 0.8, 15 = 0.5.
즉 웨이브 5 이후로는 한 방에 안 죽고, 후반은 연쇄·배율이 있어야 따라잡는다.
게이지를 언제 쏘느냐에 따른 봇 클리어율 (챕터 2, 100판): 35%에서 쏘면 29%, 꽉 채우면 63%. 피해가 게이지^1.4 로 커지고 반경도 작아서 연타보다 모아 쏘기가 확실히 낫다.

실제 테스터 기록은 타이틀 화면의 "플레이 기록 내보내기"로 같은 형식(JSON)을 받을 수 있다.

## 구현 범위 (기획서 대비)

| 항목 | 상태 |
| --- | --- |
| 모으는 탭 (게이지 3초에 100%, 탭하면 전부 써서 반경 0.4R~1.0R = 24~60, 피해 1.8D × 게이지^1.4) | ✅ 플레이 피드백으로 기획서의 "충전 3칸"을 대체 |
| 피해 배율 (곱연산, HUD 에 ×1.32 처럼 표시): 중간 보스 처치 ×1.1, 과열 코어 ×1.15/중첩, 연쇄 공명 10처치마다 ×1.03, 판 배율 상한 ×4 | ✅ 플레이 피드백으로 추가 |
| 탭 폭발 가장자리 감쇠 (중심 100% → 가장자리 50%) | ✅ 플레이 피드백 (원 안이 전부 한 방에 죽지 않게) |
| 연쇄: 폭발형·보스만 기본으로 터짐, "연쇄 반응" 증강이면 모든 적 | ✅ 플레이 피드백 (기획서는 모든 적이 연쇄) |
| 이월 피해: 연쇄 폭발 피해 = 체력을 넘긴 피해 (폭발형·보스는 + 자기 폭약 D×1.2·1.8) | ✅ 플레이 피드백으로 기획서의 "연쇄 피해 D×60%"를 대체. 연쇄가 저절로 약해지다 끊김 |
| 연쇄 배율 (처치당 +5%) | 🟡 폭발형·보스의 자기 폭약에만 곱함 (넘친 피해에 곱하면 복리로 끝없이 커져서) |

| 무리 스폰 (6~19마리, 대열 유지, 돌격형만 튀어나감), 적 속도 ×0.6 | ✅ 플레이 피드백으로 추가 (기획서는 한 마리씩) |
| 화면 안 적 상한 240, 넘치면 다음 무리를 자리 날 때까지 미룸 | ✅ |
| 웨이브 곡선 HP(w) | 🟡 기획서 공식 꼴은 그대로, 시작 체력 8 → 13, 증가율 1.16 → 1.22. 챕터별 체력 배율 1·1.15·1.35·1.6 |
| 챕터 4개 (15웨이브 + 최종 보스), 앞 챕터 클리어 시 다음 챕터 열림 / 엔드리스 | ✅ 챕터마다 적 종류가 하나씩 늘어남 (기획서는 챕터 6개) |

## 다음 단계 (프로토 v3 통과 기준까지)

4. 테스터 배포: `npm run build` 결과를 GitHub Pages 등에 올리고 링크 공유
5. 플레이 기록 수집 → 자동 플레이 리포트와 비교
