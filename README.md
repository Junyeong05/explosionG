# 연쇄 폭발 (explosionG)

탭 한 번으로 놓은 폭발이 적에서 적으로 번지고, 판 안에서 고른 증강이 그 연쇄를 키우는 세로 화면 모바일 로그라이트.

- 기획서: [`docs/design/game-design-v0.1.md`](docs/design/game-design-v0.1.md)
- 구조 설명: [`docs/architecture.md`](docs/architecture.md)

이 저장소는 **프로토 v3 개발 틀**이다. 코어 루프(탭 → 연쇄 → 레벨업 증강 → 보스 → 판 종료 → 영구 강화)가 처음부터 끝까지 돌아가고, 콘텐츠를 데이터로 계속 붙여나갈 수 있게 잡아뒀다.

## 빠른 시작

```bash
npm install
```

```bash
npm run dev
```

터미널에 뜨는 `Network:` 주소를 같은 와이파이의 휴대폰 브라우저로 열면 바로 터치로 해볼 수 있다.

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 (LAN 공개). 콘솔에서 `__app.world` 로 sim 상태 확인·조작 |
| `npm test` | 규칙 테스트 (연쇄·적 종류·증강·결정론·세이브) |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | 타입 검사 + `dist/` 정적 빌드 (어디든 올리면 됨) |
| `npm run autoplay -- --runs 200` | 헤드리스 자동 플레이로 밸런스 리포트 |

## 엔진: 웹(TypeScript + Canvas2D)으로 시작한 이유

기획서 오픈 질문 "Unity vs 웹 기반"에 대해, 다음 단계(프로토 v3: 테스터 5~10명, 지표 확인)에 맞춰 웹으로 잡았다.

- 링크 하나로 테스터에게 배포 → 빌드·심사 없이 하루에도 몇 번씩 수치를 바꿔 돌릴 수 있다.
- **게임 규칙(`src/sim`)은 DOM·렌더링과 완전히 분리된 순수 TS**라서 Node 에서 수백 판을 몇 초 만에 돌릴 수 있다 (자동 플레이 검증).
- 출시는 Capacitor 로 감싸 iOS·Android 앱으로 낸다. Unity 로 옮기기로 하면 `src/sim` + `src/data` 를 C# 로 옮기고 테스트를 그대로 기준으로 삼으면 된다.

## 폴더 구조

```
src/
  core/      난수(시드), 오브젝트 풀, 공간 격자, 수학 — 엔진 독립 유틸
  data/      ★ 기획 데이터: 수치(balance), 적, 보스, 챕터, 증강, 영구 강화
  sim/       ★ 게임 규칙. 결정론, DOM 없음. World(한 판), 증강 매니저, 봇
  meta/      아웃게임: 세이브, 영구 강화 구매, 판 종료 정산
  render/    Canvas2D 렌더러 + 연출(링·파티클·피해 숫자·흔들림, 전부 상한 있음)
  feedback/  사운드(WebAudio 합성), 진동, 슬로모션
  input/     포인터 → sim 명령
  ui/        메뉴 화면 (타이틀, 영구 강화, 증강 선택, 일시정지, 결과)
  app/       화면 흐름 + 고정 스텝 루프
tests/       vitest
tools/       autoplay.ts (밸런스 리포트)
docs/        기획서, 구조 문서
```

## 콘텐츠 추가하기

대부분 `src/data/` 파일에 객체 하나 추가로 끝난다.

| 추가할 것 | 파일 | 방법 |
| --- | --- | --- |
| 증강 | `data/augments.ts` | `AUGMENTS` 에 추가. 숫자 강화는 `modifyStats`, 규칙은 `hooks.onKill / onExplosion / onTick`, 획득 즉시 효과는 `onAcquire` |
| 진화 | `data/augments.ts` | `evolution: { requires, replaces }` 를 단 증강 |
| 적 | `data/enemies.ts` | `ENEMIES` 에 추가 (`unlockWave`, `spawnWeight`, `deathBlast`, `shields` 등) |
| 보스 | `data/bosses.ts` | `boss.onDamaged` 로 패턴 구현 |
| 챕터 | `data/chapters.ts` | 웨이브 수, 보스, 적 가중치 보정 |
| 영구 강화 | `data/upgrades.ts` + `sim/stats.ts` | `MetaModifiers` 에 필드 추가 후 `apply` |
| 기본 수치 | `data/balance.ts` | ⚠ 표시는 기획서에 값이 없어 임시로 넣은 것 |

증강 훅 규칙: **훅 안에서는 적에게 직접 피해를 주지 않고 `api.spawnExplosion` 으로 큐에 넣는다.** 그래야 훅이 훅을 부르는 재귀가 없고 결과가 결정론적이다.

## 자동 플레이 (밸런스 검증)

```bash
npm run autoplay -- --runs 200 --mode chapter
```

```bash
npm run autoplay -- --runs 200 --upgrades firepower=5,durability=2 --json autoplay-mid.json
```

기획서의 "프로토 단계에서 볼 것"을 그대로 뽑는다: 클리어율, 판 길이(목표 5~8분), 판당 최대 연쇄 분포, 사망 웨이브, 증강 선택 빈도. 봇은 사람이 아니라 **기준선**이라, 수치를 바꾼 뒤 "전보다 쉬워졌나/어려워졌나"를 비교하는 데 쓴다.

현재 임시 수치 기준 (봇 200판, 영구 강화 없음): 클리어율 약 65%, 판 길이 중앙값 약 5분, 평균 레벨 약 19, 탭당 처치 약 9.5마리, 판당 최대 연쇄 중앙값 65.
죽는 곳은 거의 전부 최종 보스(웨이브 15)다. 웨이브 도중의 압박은 아직 약하다.

실제 테스터 기록은 타이틀 화면의 "플레이 기록 내보내기"로 같은 형식(JSON)을 받을 수 있다.
